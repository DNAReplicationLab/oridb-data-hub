# One stanza per assembly, and neither is ours to host. sacCer3 is a UCSC database.
# GCF_000002945.1 is ASM294v2 (S. pombe) in UCSC's GenArk collection, which the browser
# matches automatically from the accession: declaring the genome and a trackDb is enough,
# and UCSC supplies the sequence, the gene annotation, the repeats and the chain/net to
# cerevisiae that this hub never could. A hub that hosted its own pombe assembly would
# have to carry a 2bit, groups.txt and a description page, and would show the reader the
# OriDB tracks over bare sequence.
#
# Sequence names: GenArk's chromAlias for this assembly lists I, II, III and MT as the
# `assembly` naming, which is what these track files use, so they need no renaming.
#
# In a browser URL a GenArk assembly is addressed as genome=GCF_000002945.1, never db=,
# which names only a UCSC database.
#
# <genome>/<genome>.2bit and <genome>.refNameAliases.txt stay in the directory: they are
# not for UCSC, which fetches sequence from its own servers, but for the viewer embedded
# in oridb.org, which reads the reference in the reader's browser and so needs a copy
# served with CORS headers.

genome sacCer3
trackDb sacCer3/trackDb.txt

genome GCF_000002945.1
trackDb GCF_000002945.1/trackDb.txt
